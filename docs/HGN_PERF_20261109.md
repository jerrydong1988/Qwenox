# HGN 性能选项与本机对照

自维护分支引入上游 [aa76175](https://github.com/IIIIIllllIIIIIlllll/Qwenox/commit/aa761753ea23fd302be0245c07580dd5e7875150) 的两项解码融合，以及 [1bc1986](https://github.com/IIIIIllllIIIIIlllll/Qwenox/commit/1bc19869b9ee645cb1259e91a86dd0f3d3fc1213) 的短预填充算法复用思路。Qwen27 使用本分支的 GPU 行归约内核。四个开关可在对应部署的 `service.conf` 设置，重启该实例后生效。

仓库的 `service.conf` 和 Windows Flash 混合配置均开启以下三项 Flash 优化。每项可单独设为 0 关闭。直接运行引擎且省略这些变量时，三项均关闭。

| 变量 | 启动配置默认值 | 生效范围 |
|---|---:|---|
| `GDEC_QWEN27_GPU_GREEDY` | 1 | 27B 主模型贪心、逐行目标验证、MTP 草稿选词。传回每行的 token ID，遇到非有限值返回错误，并列时取最小 ID。设 0 使用 CPU 对照路径。目标采样和概率评分仍读取完整分数。 |
| `GDEC_GR_COMBINE_SIG` | 1 | 将 Flash 单 token 主干和 MTP 的门控 sigmoid 合入后续计算，减少一次内核调用。 |
| `GDEC_AXPY_SG_OUT` | 1 | 将 Flash 单 token 的专家求和直接写入输出，每次省去 10 KiB 的设备内复制。 |
| `GDEC_LT_BUCKET` | 1 | 服务端短预填充（最多 1,024 行）按 64 行区间复用 dense hipBLASLt 算法。实际矩阵描述符始终使用真实行数。逐形状检查算法和工作区，遇到不支持的形状或同步提交失败时回到精确行数选型。推测验证沿用原路径，启用 strided MTP 时保留其 2560×2560 专用选择。 |

## Windows / gfx1151 实测

对照引擎来自自维护提交 `386d695`。在同一台 Ryzen AI Max+ 395 上，Flash 使用 HGN v2、aligned、MTP gamma 2、双槽，27B 使用 HGN、补偿预填充、MTP gamma 3、单槽。两者测试上下文均为 8,192。每次启动独立进程，以相同顺序发送请求。27B 顺序为基线、开、开、关。Flash 首轮从基线开始，第二轮先测组合开关，再测全关和各单项。请求串行发送，Flash 的槽位数描述服务配置。

各次运行的耗时和输出指纹见[测试数据](benchmarks/hgn-perf-20261109.json)。下列百分比按三条固定提示各生成 72 个 token 的解码总用时计算，正值表示吞吐提高。两轮测试未固定 GPU 时钟。每轮都核对输出 token、MTP 轮数、接受数和提议数，另用固定种子的采样请求核对返回的 logprob。

| 开关 | 普通贪心解码，两轮 | MTP 贪心解码，两轮 |
|---|---:|---:|
| 27B GPU 选词 | +0.89%、+0.18% | **+2.09%、+2.20%** |
| Flash 门控融合 | +0.51%、+0.69% | −0.40%、−0.76% |
| Flash 专家直写 | +1.06%、+0.11% | +1.60%、−0.69% |
| Flash 两项融合一起开启 | +0.79%、+0.89% | +0.90%、−0.39% |

Flash 算法复用单独开启时，在保留提示前缀、连续 12 轮分别追加 79–137 个 token 的回放中，两轮平均每次首 token 时间分别缩短 **6.96 ms、11.33 ms**。算法分组选型可能影响浮点舍入，结论限于这组输入。三个 Flash 开关同时启用时，两轮 MTP 解码吞吐分别变化 −1.41%、−0.62%。

GPU 回归入口为 `build_win.sh v006-test` 和 `build_win.sh test`。其中 `v006-test` 需要通过 `TOK_DIR` 指定 Flash tokenizer 目录，并会检查融合内核的 FP32 位模式、八行选词的并列值、正负零、NaN 和无穷值。

计时使用显式开关的候选构建。最终构建另行复测了 27B 默认配置的 MTP gamma 3 和 DFlash2 gamma 7，生成 token、草稿统计及返回的 logprob 均与基线一致。Flash 最终构建在三项全关和三项全开的回放中，生成 token、草稿统计和缓存命中长度一致，44 个返回的 logprob 差值均为零。短预填充日志记录到 162 次通过实际矩阵形状检查的算法复用。
